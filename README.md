# Steam Walker — MVP

用一台机器上真实的 Steam 游玩记录，生成一条"按年份往回走"的走廊。每一款游戏是一只猫，身上带着它的评价与你的态度。

## 打开

**只看默认库**：直接双击 `index.html`（数据内联在 `library.js`，file:// 完全可用）。

**从开始界面查看别人的公开库**：Steam 不给 `steamcommunity.com` 发 CORS 头，浏览器不能直接读，所以本目录带了一个只读代理。

**最省事**：双击 `start.bat`，它会启动服务器并自动打开浏览器。

手动启动：

```
py -3 server.py
```

然后打开 http://127.0.0.1:8765/ 。直接双击 `index.html` 也可以，只要 `server.py` 同时在 8765 跑；否则页面会尝试公共代理，可能被 Steam 拦截。

旧的 `py -3 -m http.server 8765` 仍然能打开默认库，但它没有 `/api/steam`，看不了别人的公开库。

## 操作

| 键 | 作用 |
| --- | --- |
| W A S D / 方向键 | 行走 |
| Shift | 奔跑 |
| E | 走近某人后打开菜单：说话 / 跟随 / 让两只猫互动；回头面对跟随猫可让它回去 |
| 1–9 | 选择菜单项 |
| G | 让当前跟随的猫回到原位（和菜单里的「让 TA 回去」等价） |
| Esc | 关闭菜单 / 松开鼠标 |
| M | 音乐静音（猫叫不受影响） |

走近 3.4 米内、并且面朝它时浮出对话卡；按 E 会先听到一声猫叫，再打开菜单。菜单第一项是原来的完整对话（最多 7 句）。

## 查看另一个公开库

开始界面有一个输入框，粘贴 Steam 个人资料链接（`https://steamcommunity.com/id/...` 或 `https://steamcommunity.com/profiles/<17 位 ID>`），按「查看」。

- **公开且有游戏**：读取公开的 `games?xml=1`，用这个账号重新生成走廊。
- **私密 / 隐藏 / 没有公开游戏**：显示 **「那是座封闭花园」**。
- **网络或代理失败**：显示「花园的门暂时打不开，等一下再试。」
- 进入别人的库后，输入框下面会出现「← 回到默认账号的走廊」，点它清除本次数据并回到 Kaskade_16。

公开 XML 只有 appid、名字、时长，没有入库年份、类型、最后游玩、好评率和成就，所以外账号的走廊会：
- 全部排在 2026 一段，按游玩时长从多到少
- 类型显示 Unknown，毛色统一偏灰
- 没有星星、花环、十字架；对话里的“最后游玩/成就/好评”会留空或说不知道
- 0 小时的游戏也会出现（Steam 的公开列表包含它们）

代理只放行 `steamcommunity.com`，只读、不登录、不写回 Steam。

### GitHub Pages

GitHub Pages 是纯静态托管，跑不了 `server.py` 的代理，所以**在线站点只展示默认的 Kaskade_16 走廊**；开始界面的公开库输入仍会出现，但需要在你自己的电脑上运行 `start.bat` / `server.py` 才能查询。页面在 `*.github.io` 下会自动把输入框下的提示改成“在线版只展示默认库”。

## 数据

- **339 款游戏**，**10,688 小时**
- 游戏列表 / 时长 / 最后游玩：`IPlayerService/GetOwnedGames`（远端账号数据，含从未安装的游戏）
- 成就：`GetPlayerAchievements` 逐游戏查询
- 好评率：商店页 "X% of the N user reviews for this game"
- 你的评测：`steamcommunity.com/id/HeresyFire/recommended`（47 推荐 / 3 不推荐）
- **入库日期**：`store.steampowered.com/account/licenses/`（563 条许可，2016—2026）

### 关于"入库年度"

走廊按**加入游戏库的年份**分段，不是按最后游玩。覆盖情况：

| 来源 | 数量 |
| --- | --- |
| 许可页确有日期 | 277 |
| 无许可记录，用最早成就时间估计 | 26 |
| 完全无从考证（零售 Key / 礼物 / 已移除）| 36 |

最后这 36 款（含 CS2、巫师 3、黑神话、剑星、只狼）被放在 **2016**，对话里会说"我不记得你是什么时候把我加进来的"。

年度分布：2016: 47 · 2017: 41 · 2018: 49 · 2019: 22 · 2020: 40 · 2021: 37 · 2022: 20 · 2023: 17 · 2024: 20 · 2025: 26 · 2026: 20

### 参考

- [The Pudding — Life after death?](https://pudding.cool/2026/10/lifeafter/) by Alvin Chang：用空间化的方式浏览调查数据的交互叙事，是本作“走进数据”方向的重要参考。

同一份 geometry 实例化 339 次，只发一个 draw call。

**花色**（按 appid 哈希稳定分配，约 35% 纯色 / 30% 虎斑 / 15% 燕尾 / 10% 三花 / 10% 暹罗）：

| 花色 | 做法 |
| --- | --- |
| 纯色 | 类型色直接当毛色 |
| 虎斑 | 沿身体轴取 `fract(z*7)` 的条带，压暗 55% |
| 燕尾 | 深色底 + 腹部/胸口的白色遮罩 |
| 三花 | 白底 + 橙色块 + 深色块，用 3D 噪声切分 |
| 暹罗 | 奶白底，四肢/耳/尾端点压成深色 |

猫全部侧身面向走廊中线，走过时能看到侧脸。

好评率决定**毛的浓密程度**：

| 好评率 | 毛量 | 观感 |
| --- | --- | --- |
| 95—100 | 1.0 | 绒密、几乎看不出皮肤 |
| 85—95 | ~0.85 | 厚实，毛流清晰 |
| 70—85 | ~0.7 | 正常毛量 |
| 60—70 | ~0.5 | 稀薄，能看到皮肤 |
| 40—60 | ~0.3 | 斑秃 |
| <40 | 0.22 | 几乎秃，只剩几缕（还会招苍蝇） |

毛是片元着色器里的各向异性噪声（沿 Y 轴拉长成毛流），`edge = 1 − fur*0.92` 决定"多少面积被毛盖住"，露出来的部分用更深的皮肤色。顶点着色器还会沿法线做一点抖动，让边缘发毛。

## 猫的日常

### 猫叫

按 E 打开菜单时会先叫一声。**25 种**叫声全部由 WebAudio 实时合成，没有音频素材：

- 锯齿波声门源 → 三个移动的带通滤波器（F1/F2/F3 共振峰）→ 包络 / 颤音 / 气声
- 25 组预设覆盖短喵、长喵、疑问、撒娇、低吼、双连/三连、奶喵、老猫、mrrp、啾、长嗷、哇、哼、急喵、气声、大笑喵等
- 每只猫有**固定声线**：体型越大基频越低（`f.s`），appid 哈希再给一点音高偏移；同一只猫每次叫还有 ±1.5% 音高、±3% 速度的随机
- 播放时 `playbackRate` 管快慢、`detune` 管音调，两者独立——所以同一个预设换一只猫就是另一种腔调
- 左右声像跟着猫相对玩家的位置走

### 跟随

菜单第二项是「让 TA 跟着你」。猫沿你**实际走过的路线**跟在后面（约 2 米，略偏右 0.75 米），按移动方向转身，走路时有轻微起伏。**只转动视角不会让它移动或转身**；你停下时它就停在原地、保持朝向；你开始走，它才继续沿路径跟上。这时转过身面对它按 **E**，菜单第二项会变成「让 TA 回去」，选它之后猫会自己慢慢走回原来的位置（按约 2.4 米/秒，距离越远走得越久）。同一时间只带一只；让另一只跟随会把前一只送回家。也可以直接按 **G** 让跟随的猫回原位，HUD 左下角会显示当前跟随者。

### 两只猫互动

身后有跟随的猫时，走到别的猫面前按 E，菜单会多出一项「让「A」和「B」互动」。选项右侧用小字写着这次的概率，例如「贴贴 52% · 打架 48%」。**它不让你再选贴贴或打架**，选一次互动后按这个概率直接判定结果。

**数据趋同率**（0–100%）由两人的游戏数据算：

| 维度 | 权重 |
| --- | --- |
| 主类型相同 | 26% |
| 总时长（对数差） | 22% |
| 好评率差 | 16% |
| 最后游玩时间差 | 13% |
| 成就完成度差 | 12% |
| 你的推荐/不推荐是否一致 | 6% |
| 发行年差 | 5% |

贴贴概率 = `8% + 87% × 趋同率`，夹在 8%–95%；打架概率就是剩下的部分。所以越像越容易贴，越不像越容易打。互动选项右侧会直接写出这两种结果的概率。

- **贴贴**：两只猫并排站到一起（中心距 0.56 米，毛贴着毛），身体轻微前后蹭动，头顶飘 ♥ 和「呼噜…」；声音是合成的呼噜——布朗噪声过 260Hz 低通和 470Hz 带通，再用 25–29Hz 的 LFO 做振幅调制，叠一个 58Hz 的胸腔低音
- **打架**：两只猫保持约 1.55 米面对面，绕圈、前扑、头顶冒「！」，并周期性飘出「老吴——」；声音是合成的「老吴对视」——就是两只猫对峙时那种拖长的「老——吴——」，先「lao」后「wu」的长嚎（F1/F2 从开口滑到闭口），四声错开、一高一低，中间夹着哈气
- 两段互动都精确持续 **10 秒**（从靠近完成开始计时，HUD 顶部有倒计时）。10 秒后跟随的猫继续跟随，被互动的猫用 1.25 秒走回自己原来的位置和朝向

### 路过时

- 距离 4.8 米内、总时长 **≥ 2 小时**的猫会转身看向你；你走远后转回原来的朝向
- 总时长 **0 小时**（没真正玩过）的猫，每次进入这个范围有 **10%** 概率朝你哈气：一声合成哈气 + 头顶「哈——」，并有 15 秒冷却
- 看向/哈气都是整只猫转身（模型没有骨骼），眼睛、花环、十字架、地上的光晕、星星会一起跟着转

## 音乐

原曲《Waterfall - Spa》（Trademarks & Copyrights，190.64 秒，44.1kHz 立体声，RMS −23dB）。

**循环改造**：把最后 3 秒淡出、叠到最前面 3 秒上（`afade in/out` + `amix`），再做 `concat`，得到 187.65 秒的无缝版本——输出结尾与开头是同一个采样点，接缝处没有断点。重编码为 Opus/OGG（2.2MB，Opus 没有 MP3 那种帧填充空白），Base64 内嵌在 `bgm-data.js` 里。

**为什么内嵌**：`file://` 下浏览器禁止 `fetch` 本地文件，只有把音频变成 JS 字符串才能解码成 AudioBuffer。播放用 `AudioBufferSourceNode.loop = true`，是采样级精确循环，不会有 `<audio loop>` 的几十毫秒空隙。

**年份联动**：`age = 2026 − 当前年份`

| 走在 | age | 低通截止 | 底噪 |
| --- | --- | --- | --- |
| 2026—2021 | ≤5 | 18 kHz | 0 |
| 2020 | 6 | 16.1 kHz | 0.017 |
| 2018 | 8 | 12.2 kHz | 0.051 |
| 2016 | 10 | 9.1 kHz | 0.080 |

底噪是白噪声过一个中心 3.6kHz 的带通，所以是"沙沙的高频"，配合音乐被削掉的高频，听起来像旧磁带。两处都用 `setTargetAtTime` 做 0.9 秒过渡，跨年份不会突变。

按 **M** 静音/恢复，左下角 ♪ 跟着变暗。`?auto=1` 不播放。

内存代价：264 秒的音频解码成 float32 大约 70MB。嫌重可以把 `startMusic` 换成 `<audio>` 直放，但 loop 会有轻微缝隙。

## 已知限制

- 猫没有骨骼，"看向你"、贴贴、打架都是整只猫的转身/位移，不是逐关节动画
- 同一时间只带一只跟随猫；让它换成另一只时，前一只会自己走回去
- 猫之间没有碰撞，跟随猫会从别的猫身边穿过去
- 所有猫叫、呼噜、哈气、老吴对视都是合成音，不是录音
- 109 款总时长 0 小时的游戏会参与"10% 哈气"，但不会主动看你
- 53 款拿不到好评率，用白银兜底
- 129 款没有成就数据，不会有星
- 36 款查不到入库时间，全部堆在 2016（对话里会承认这件事）
- 外账号模式只能拿到公开 XML 的 appid / 名字 / 时长，所以没有年份、类型、最后游玩、好评和成就；全部落在 2026 一段、类型 Unknown、没有星星/花环/十字架
- 外账号模式依赖 `server.py` 的本地代理；Steam 的公开 XML 端点和公共 CORS 代理都可能被限流或拦截，失败时会显示“花园的门暂时打不开”
- 私密、隐藏游戏或没有公开游戏的账号统一显示“那是座封闭花园”，不区分具体原因
